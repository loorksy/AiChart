## Confirmed findings before corrective changes

1. **MF-001 — Critical:** production fabricates a fully capable model registry from three hardcoded IDs on cache miss.
2. **MF-002 — Critical:** the candidate-authority detector does not block a contaminated outbound request.
3. **MF-003 — Critical:** canonical trading HTTP adapter permits `store:true`.
4. **MF-004 — Critical:** numeric multi-timeframe evidence and independently fetched Vision images are not guaranteed to share one immutable snapshot or complete context ladder.
5. **MF-005 — Critical:** production capability claims for streaming/tools/context/cancellation/timeout and multi-image are not actually probed.
6. **MF-006 — Critical:** active MCP workspace instructions still require candidate binding, while scan paths expose directional rankings/signals.
7. **MF-007 — High:** unsupported reasoning values and unavailable saved models can be silently substituted/downgraded.
8. **MF-008 — High:** request cancellation does not propagate to the provider, and silent model substitution is not detected.
9. **MF-009 — High:** per-run model, reasoning, response, usage, snapshot, image, validator, and repair provenance is not durably recorded.
10. **MF-010 — High:** user-context Vision can include the wrong drawing collection and is not gated by actual request dependency.
11. **MF-011 — High:** post-decision technical validation is incomplete for required broker/snapshot constraints.
12. **MF-012 — Medium:** internal validator codes can leak into user-facing risk warnings.

## Release decision at matrix freeze

**NO-GO.** The active production baseline is healthy and remains the rollback target, but the corrective branch must not be merged or deployed while any Critical release gate above remains failed or unverified.

## Corrective branch verification after matrix freeze

The following source-level corrections are now present on this branch and have local evidence:

- Production paths no longer call `stubProbedRegistry`; capability records load from the durable `system_flags` registry only, with a 24-hour freshness bound (`web/src/lib/agent/modelFirst/modelRegistryStore.ts`).
- The Responses trading adapter hard-codes `store: false`, rejects provider model substitution, and propagates the orchestrator abort signal (`web/src/lib/agent/modelFirst/openaiResponses.ts`, `runModelFirstDecision.ts`).
- Candidate-authority detection is recursive and fail-closed before provider I/O (`buildNeutralEvidence.ts`, `safetyContracts.test.ts`).
- The active orchestrator freezes a real bid/ask quote, fetches missing canonical context timeframes, verifies neutral image completeness/freshness, and passes only user-owned drawings to user-context Vision (`decisionQuote.ts`, `orchestrator.ts`, `neutralVision.ts`).
- Per-run model/provider/response/usage/snapshot/validator/repair metadata is written to the internal run trace and stripped from client output (`types.ts`, `chat/stream/route.ts`, `userSafeOutbound.ts`).
- Unsupported reasoning and revoked saved models now require explicit reselection; the model-only path never silently downgrades (`modelRegistry.ts`, `userModelPreferences.ts`).
- Broad opportunity scans no longer select the first actionable result; multi-symbol deep scans return a comparison-required state instead of issuing a deterministic first-result recommendation (`opportunityScan.ts`).

Local gates completed after the corrective edits: web TypeScript, MCP TypeScript, 20 model-first tests, 319 web unit tests, 53 decision-authority tests, 36 context tests, 70 MCP catalog/UI tests, 8 Trading DNA tests, 8 canonical recommendation tests, and 2 integration tests (one Redis round-trip skipped because Redis is not running). An active test account is now available, but the authenticated MCP live-tool sweep still cannot mint a production-compatible token because the local `MCP_AUTH_SECRET` and `AICHART_SERVICE_TOKEN` values are not configured. No secret values were requested, printed, or persisted.

`npm run build` also completes successfully (Next.js production build, TypeScript, page generation); it emits existing NFT-trace and metadata-theme warnings.

Repository-wide `npm run lint` remains non-green because the vendored `realtime-voice-component` has 23 existing React-hook errors (plus 157 warnings); this is recorded as a separate baseline gate and was not mass-edited during the trading audit.

### Authenticated production browser evidence (2026-07-18)

- The Arabic RTL dark desktop console authenticated successfully with the supplied active test account; no password was stored or written to repository files.
- The production selector exposed `gpt-4.1`, `o3-mini`, and `o4-mini`. GPT-4.1 showed no adjustable reasoning control. O4 Mini showed high/medium/low with high selected by default.

- One bounded EURUSD 15-minute analysis was submitted with explicit instructions not to execute or draw. The chart remained on EURUSD/15m and no recommendation was emitted. The request failed with `Decision model was unavailable — no market recommendation was issued`, proving fail-closed behavior but also proving that production exposed an unavailable model.

Because the test also created a new conversation, this is recorded as a high-severity unresolved chart-invariance signal rather than conclusive attribution to Vision capture. The corrected build must test drawing identity/count before and after both success and failure without switching conversations.

These are branch-only facts. Production still exposes the pre-correction fallback registry until a reviewed, green deployment occurs; therefore the release decision remains **NO-GO**.
